一、总览与术语

1. 一句话定义

一局不对称限时攻防：防守方用短暂窗口埋下信标，进攻方随后限时拆除。信标全灭则攻方胜，撑到时间结束则守方胜。

2. 设计支柱（Design Pillars）

  • 不对称但公平：攻防能力镜像互补，胜负取决于执行力而非先天强弱。
  • 时间即压力：放置阶段的"盲"与进攻阶段的"钟"，共同制造倒计时的紧迫感。
  • 随机搅局：事件系统定期打破均势，逼两队不断重新评估局势。
  • 成长正反馈：击杀与破标带来技能升级，让优势方滚雪球、劣势方看到翻盘窗口。

3. 一局的生命周期（节奏地图）

大厅集合 → 加入队列 → 管理员开局
   ├─ 放置阶段（守方睁眼埋雷，攻方被蒙眼锁死）
   └─ 进攻阶段（限时拆标 + 事件搅局 + 技能对撞）
        ├─ 信标全灭 → 攻方胜
        └─ 时间耗尽仍有信标 → 守方胜
   → 5 秒结算复原 → 回大厅

二、核心对局流程

1. 这个系统要解决什么

把"一群人想打一局对抗"变成一段有起承转合的体验，而不是一上来就乱斗。核心是用两个阶段制造节奏断层：先给守方一段"安心建设"的时间，再突然拉开对抗的闸门。

2. 玩家实际经历什么

开局：管理员确认开局后，所有人被拉进对局、分队（攻/防交替分配）、发装备。世界规则切换：背包保留、友伤关闭、时间定格正午、刷怪关闭——营造"干净擂台"感。

放置阶段（守方窗口 / 攻方无力期）：守方睁眼，抓紧埋信标；攻方被蒙眼 + 锁在原地，只能转头，物理上无法靠近。倒计时归零前 10 秒有滴答提示。

进攻阶段（对抗期）：闸门拉开——攻方致盲解除、PVP 开启、守方开始全程发光。限时拆标开始，所有其他系统（事件、技能、HUD）在此刻全面激活。

结算：胜负判定后，有 5 秒"谢幕"再复原世界，给玩家消化结果、看统计的时间。

3. 胜负与队伍

  • 攻方胜：拆光所有信标，或守方一个都没埋（放置结束即判负，逼守方至少动手）。
  • 守方胜：时间耗尽仍有信标残留。
  • 队伍交替分配（先来先攻），避免抱团；玩家也能手动换边，但对局进行中锁死，防止临阵倒戈。

4. 关键数值与平衡基线

参数当前值设计意图
信标数3守方容错 = 攻方工作量
对局时长10 分钟进攻压迫上限
放置时长100 秒守方建设预算
装备层级钻石统一 baseline
清理半径256 格局末扫除上局残留信标
即时重生开死亡不丢装备、秒回
单位雷区 对局时长按"分钟"算，放置时长按"秒"算——两套单位极易在文案/配置里混淆，是设计沟通的高频坑。

5. 它和别的系统怎么咬合

  • 给信标系统发令：开局/终局清场，胜负直接读"还剩几个信标"。
  • 给技能系统发令：进攻阶段开始时分配路线、解锁 UI。
  • 给事件系统发令：把总时长交给事件系统，让它按百分比播事件。
  • 给HUD喂数据：剩余时间、剩余信标都从这儿出。
  • 给统计发信号：对局结束事件触发战绩结算。

6. 设计红线与边界

  • 攻防出生点必须同世界：否则对局物理上不成立，直接拒绝开局。
  • 守方 0 信标即负：强迫守方至少埋 1 个，避免出现"守方躺平赢"。
  • 结算 5 秒锁：期间拒绝开新局，防止状态撕裂。
  • 钳制不一致是隐患：对局时长允许 1–120 分钟但界面只放 1–60，信标数代码无上限但界面限 1–10。体验上限以界面为准。
  • 无信标专属回血：整张图靠"局末整体复原"还原，保证破坏是永久的、推进是真实的。

三、信标系统

1. 这个系统要解决什么

信标是整局游戏的唯一胜负轴。它把"攻防对抗"收敛成一个所有人都看得懂的目标：守方护住几个点，攻方端掉它们。没有信标，对抗就散了。

2. 玩家实际经历什么

  • 埋（放置阶段，仅守方）：守方在蒙眼攻方面前抓紧把信标摆进战场。同一点不能重复埋。信标数量 = 守方的"容错次数"。
  • 护（进攻阶段）：阶段一开始，守方背包里多余的信标被清空（防偷偷补埋），且守方全程发光——等于头顶写着"来打我"。
  • 拆（进攻阶段，仅攻方）：攻方破坏信标时不掉落物品，信标数 -1。拆到最后一个归零 → 攻方直接获胜，全场播报。
  • 找：进攻方手里有"信标指南针"始终指向最近信标；平时信标本身不发光，仅临近终局（99% 事件）才被点亮高亮。

3. 关键数值与平衡基线

项当前值设计意图
默认信标数3守方容错 = 攻方工作量
拆标掉落无破坏即永久，避免刷物
指南针指向最近信标降低无效游走
守方发光全程用"被标记"换攻方清晰目标
残留清理256 格局末扫清上局信标
终局高亮仅 99% 事件终盘视觉爆点

4. 它和别的系统怎么咬合

  • 给核心流程：信标数归零 = 攻方胜；放置结束 0 信标 = 攻方直接胜。
  • 给技能系统：破标后给攻方全队一个短暂强化（"拆完爽一下"的正反馈）。
  • 给HUD：剩余信标数全场可见，是玩家最关心的数字。
  • 给统计：每次破标计入战绩。
  • 给竞技场：信标必须落在战场范围内。

5. 设计红线与边界

  • 无独立管理器：信标逻辑分散在"放置/破坏监听"与"对局主循环"两处，改机制要两头同步。
  • 活塞可推信标：允许用活塞转移信标，是设计内允许的"狡猾玩法"，指引坐标会同步更新。
  • 虚空无地面：战场是悬空的，信标必须靠守方自己搭台子——这是"建设"乐趣的来源，也是新手最容易卡住的地方（需引导）。
  • 0 信标即负：守方必须至少埋 1 个，堵死"躺平赢"漏洞。
  • 阶段切换清背包信标：防止进攻阶段开始后被偷埋。

四、技能系统

1. 这个系统要解决什么

纯靠拆/埋会很快变成"谁人多谁赢"。技能系统给个人一层成长与风格：随着对局推进，玩家解锁主动技能、选择战斗路线，让操作与决策产生差异，拉开高手与新手的差距。

2. 玩家实际经历什么

  • 选路线（开局前）：三条路线对应三种战斗性格——突袭（正面硬刚）、干扰（控场恶心人）、辅助（保队友）。未选时按阵营自动分配（进攻→突袭，防守→干扰），但辅助只能手动选。
  • 靠击杀解锁（滚雪球）：每击杀累积，跨过门槛（1 / 2 / 4 杀）解锁下一层。每次解锁全队补发补给（箭/金苹果）。
  • 靠事件升级：60% / 80% 事件会触发"技能强化"，全队技能层级 +1。
  • 释放：技能是手里一颗"星"，右键即放，有冷却。仅进攻阶段可用。

3. 技能数值与平衡基线

路线技能解锁击杀冷却效果（设计层）
突袭破阵130s自身力量，短促爆发
突袭冲锋225s向前的猛冲（位移）
突袭湮灭460s范围伤害 + 自身力量，团战核武
干扰致盲130s最近敌人失明，断其视野
干扰禁锢245s范围内减速+挖掘疲劳，锁死对方
干扰枯竭470s范围内虚弱+饥饿，慢性放血
辅助补给140s发箭/金苹果/石头，续命
辅助守护250s友方抗性+回血，保排
辅助窥敌455s范围内敌人显形，开图
被动（破标增益） 每次拆掉信标，攻方全队短暂获得力量 + 向前冲量——把"拆标"和"爽感"绑在一起。

4. 它和别的系统怎么咬合

  • 给核心流程：进攻阶段开始才分配路线、解封技能。
  • 给事件系统：60%/80% 的"技能强化"直接拉全队层级。
  • 给信标系统：破标触发全队增益。
  • 给HUD：行动条末尾常驻技能状态（路线/击杀进度/冷却）。

5. 设计红线与边界

  • 仅进攻阶段可放：放置阶段锁死，避免开局秒放破坏建设窗口。
  • 冷却防刷：冷却中释放被拒并提示。
  • 冲锋用合法位移：走"速度"而非瞬移，避开反作弊误判。
  • 升级封顶：事件升级不超过路线长度，避免溢出。
  • 数值驱动优先：技能数值写在配置里，调平衡不用改代码；但新增机制类型仍需动底层。

五、对局事件系统

1. 这个系统要解决什么

纯对抗容易陷入"谁先手谁赢"的死板节奏。事件系统是一台按时间自动搅局的机器：到点就给全队发点东西、或丢个乱子，逼两队不断重新读局势。它是节奏的"呼吸阀"。

2. 玩家实际经历什么

事件不靠玩家触发，而是随进攻阶段进度自动发生。进度按"已过去的时间占比"算，所以对局越长，事件发生的绝对时刻越晚，但相对位置不变。

进度类型玩家会看到
15%固定小空投：每人 +1 金苹果（开局小甜头）
30%随机二选一敏捷进攻（攻方加速）/ 防守阳痿（守方虚弱）
50%固定大空投：每人 附魔金苹果 + 不死图腾（中期保命）
60%随机三选一核打击 / 移形换影 / 技能强化
80%随机三选一同上三个再抽一次
99%固定终局总攻：所有信标被点亮高亮，直到结束

每次触发：全屏弹事件名 + 说明、聊天广播、信标激活音效。BossBar 上还会实时显示"距下次事件还有几秒"。

随机三选一那组是真正的"搅局王"：

  • 核打击：每人头顶砸下点燃的 TNT（约 30 格高）——逼迫走位。
  • 移形换影：随机两两交换位置 10 次——瞬间打乱阵型。
  • 技能强化：全队技能层级 +1——直接拉高战力。

固定事件15 / 50 / 99%锚点式节奏，保证"必有"的关键时刻
随机组30（2选1）/ 60（3选1）/ 80（3选1）制造"不知道来啥"的悬念
随机权重等权简单公平，暂不偏袒
小空投金苹果×1开局安慰奖
大空投附魔金苹果+图腾中期保命

4. 它和别的系统怎么咬合

  • 给核心流程：进攻阶段开始接收总时长，每秒被"滴答"问一下"到事件没"。
  • 给技能系统：60%/80% 的"技能强化"直接拉全队层级。
  • 给信标系统：99% 事件把所有信标点亮，是视觉与信息的双重总攻信号。
  • 给HUD：把"下次事件倒计时"喂给 BossBar。

5. 设计红线与边界

  • 百分比驱动而非绝对时间：时长改长改短，事件相对位置不变，节奏感稳定。
  • 每个事件只发生一次：固定事件和随机组都去重，不会重复刷。
  • 当前无加权随机：想要"稀有事件"得改抽选逻辑，目前三选项平权。
  • 实体必须清理：终局高亮用的隐形支架和粒子任务，对局结束必须回收，否则会泄漏到下一局——这是已埋的坑，扩展事件时务必同理。
  • 尚未实机验证：事件系统只过了编译，触发时机/显示/随机正确性/清理都需在游戏里跑一遍确认。

六、竞技场与领地边界

5.0 机制变更 边界/权限不再由插件手写代码夹人，而是硬依赖服务端领地插件，由竞技场领地的旗标原生托管移动/进入、PvP、爆炸、火焰、流体与活塞。服务器须安装领地插件才能加载本插件。

1. 这个系统要解决什么

对抗需要一个有边界的擂台：太大则两队永远碰不上，太小则没有走位空间。边界系统定义"战场在哪、掉出去会怎样"，同时负责反作弊，保证对抗在公平框架内发生。

2. 玩家实际经历什么

  • 战场范围：竞技场是一个悬空盒子，头顶敞开、四周由领地插件锁定：非成员，以及末影珍珠、紫颂果、活塞弹射、水流带人等外力，都无法越界。立体走位与高空战术依旧是玩法核心。
  • 底面是虚空：一旦掉到盒子下沿以下，会被瞬间送回本方重生点，并清掉下坠速度，避免摔死（软惩罚，不计入战绩）。
  • 反作弊（后台）：放置阶段会锁定进攻方站位；越界、异常位移由领地旗标与后台巡检共同兜底。
  • 划地（管理员）：管理员用"领地木锄"左键/右键点两个对角框出战场水平范围；加载时后台按此范围自动建/复用领地。

3. 关键数值与平衡基线

项当前值设计意图
最小开局人数2至少能凑一攻一防
最大队列20防单局过载
边界拦截领地插件原生拦截非成员及外力原生存栏，立体玩法不受限
边界顶无（开放高空）给立体玩法空间
底面判定低于盒子下沿触发"送回重生点"
自动开局默认开但已停用现改为管理员手动确认

4. 它和别的系统怎么咬合

  • 给核心流程：三方的重生点都从这里出，开局强校验"必须同世界"。
  • 给信标系统：信标必须落在战场盒子内。
  • 给玩家状态：掉出底面回重生点的"清速度"逻辑，是防摔伤的关键。

5. 设计红线与边界

  • 边界由领地插件托管（硬依赖）：服务器必须安装领地插件，否则本插件不加载。
  • 区域可自动建：加载时按 arenas.yml 的 region-min/max 自动建/复用领地；但没划地的竞技场不会生成领地，边界仍放开。
  • 管理员豁免边界：方便调试，但管理权限要可信。
  • 无顶是刻意设计：高空战术是玩法一部分，但需服务端视距/性能支撑。
  • 回重生点不算死亡：底面虚空是传送惩罚，不进统计。
  • 自动开局已停用：实际开局靠管理员确认。

七、大厅与虚空世界

1. 这个系统要解决什么

玩家需要一个安全的中转站（大厅）和一个对局入口世界（游戏世界），两者都做成"纯虚空"——没有自然地形，一切由玩家/管理员自己搭建。把"建图"的乐趣和控制权交还给服务器运营，而不是写死在代码里。

2. 玩家实际经历什么

  • 大厅：和平、关 PVP 的休整区。里面有传送 NPC（一个写着"传送到游戏世界"的小立牌），右键即去对局入口。
  • 游戏世界：开 PVP 的入口层。真正对局实际发生在另一个"竞技场世界"，这里更像是通往擂台的走廊/候场。
  • 落点与重生点可配：管理员能设定"从大厅传到游戏世界落在哪""在大厅死了回哪""在游戏世界死了回哪"。

3. 关键数值与平衡基线

项当前值设计意图
大厅世界beacongame_lobby（PVP 关）安全区，避免休整时被偷
游戏世界beacongame_game（PVP 开）入口即对抗氛围
默认坐标(0.5, 65, 0.5)占位用，实际需要搭台
默认难度和平大厅不死不刷怪
传送媒介盔甲架伪 NPC轻量、无需额外插件

4. 它和别的系统怎么咬合

  • 给核心流程：游戏世界就是实际对局世界的"门面"，对局在竞技场世界进行。
  • 给玩家状态：非对局死亡按所在世界用对应重生点。
  • 给竞技场：大厅/游戏/竞技场是三个不同世界，传送与重生分别管理。

5. 设计红线与边界

  • 纯虚空无地面：默认坐标悬在半空，玩家落进去会掉——必须由管理员搭平台或设重生点，这是最大的"上手坑"。
  • 已生成世界不自动改：旧世界目录不会因为代码改了就变地形，需删目录重生。
  • 游戏世界会自清：游戏世界启动时会删旧目录重生为纯虚空，里面自定义结构会丢——上服前务必备份竞技场。
  • NPC 是盔甲架：不是真实体，靠标签比对识别右键，避免和真实实体混淆。

八、HUD 与提示系统

1. 这个系统要解决什么

对抗信息越清楚，玩家越能做出决策。HUD 系统的职责是把对局关键状态"无脑可读"地呈现在眼前：全局进度给 BossBar，个人任务给 ActionBar，大事件给全屏播报。

2. 玩家实际经历什么

顶部 BossBar（全局，全场可见）：放置阶段显示"还剩多少秒建设"+"已埋几个信标"+进度条；进攻阶段显示"倒计时时钟"+"还剩几个信标"+"距下次事件还有几秒"+进度条，红色调，压迫感拉满。

底部 ActionBar（个人，每秒刷新）：按你是什么身份显示不同任务——攻方放置中："你是进攻方，干等"；进攻中："拆光所有信标！剩 X 个"。守方放置中："快埋信标！已埋 X/Y"；进攻中："护住信标！剩 X 个"。旁观："观战中，剩 X 个"。末尾常驻你的技能状态（路线/击杀进度/冷却）。

大事件播报：阶段切换、信标被拆、事件触发，都会全屏弹 Title + 聊天广播 + 音效，确保"重要的事瞒不住"。信标被拆时，拆的人还会被短暂"点亮"10 秒，等于暴露"刚下手的是谁"。

3. 关键数值与平衡基线

项当前值设计意图
BossBar 刷新每秒信息实时，但不晃眼
下次事件倒计时实时秒数给玩家"预期管理"，减少突发焦虑
信标摧毁 Title停留 1.2s短促一瞥，不打断操作
事件 Title淡入1s/停留6s/淡出2s让玩家看清"发生了什么"
破标暴露发光 10s给守方"报仇对象"，平衡信息

4. 它和别的系统怎么咬合

  • 给核心流程：时间、信标数都从对局主循环取。
  • 给事件系统：BossBar 的"下次事件倒计时"直接来自事件系统。
  • 给技能系统：ActionBar 末尾的技能状态来自技能系统。
  • 给信标系统：剩余信标数是 HUD 最核心的数字。

5. 设计红线与边界

  • BossBar 长度有限：拼接段太多会被截断，新增信息务必精简（如"下次事件 Xs"）。
  • 文案双语：所有提示走多语言文件，新增须同步中英文，否则回退默认。
  • ActionBar 会被覆盖：每 tick 重写，过长文本可能显示不全。
  • 音效集中管理：BossBar/公告/事件的音效应统一出处，避免散落难调。

九、玩家状态与重生

1. 这个系统要解决什么

死亡不应等于"出局"。这套系统保证：对局中死亡秒回、不丢装备、状态归位，让对抗保持高密度、低挫败；同时用一系列"保护规则"堵住作弊与破坏，维持擂台干净。

2. 玩家实际经历什么

  • 死亡与重生：死了不掉物品、不掉经验，1 秒后自动重生回本方重生点；重生后：满血满饱、清掉药水效果、回到战斗状态。
  • 坠落保护：掉出战场底面被送回重生点时，会清掉下坠速度，避免"刚回安全点又摔死"的冤枉死。
  • 放置阶段冻结：放置阶段进攻方被锁在原地（只能转头），物理上无法接近守方——这是"建设窗口"的安全阀。
  • 指令与破坏封锁：对局中玩家不能乱飞、乱给物品、乱改世界（传送/kill/时间/天气等敏感指令被禁）。不能乱丢重要物品、不能炸方块、不能乱动容器和装饰实体——保证战场只被"玩法"改变，不被"捣乱"改变。

3. 关键数值与平衡基线

项当前值设计意图
即时重生开（1 秒后）降低挫败，保持对抗密度
重生状态满血满饱/清药水公平回起点，不滚雪球式落后
守方发光全程重生也维持"被标记"，攻方信息不丢
进攻致盲放置阶段全程重生也锁死，建设窗口绝对安全
出界提示冷却5 秒给反馈但不刷屏
指令黑名单传送/kill/时间/天气…堵住对局内破坏手段

4. 它和别的系统怎么咬合

  • 给核心流程：重生归位、装备重发、发光/致盲还原都由对局主循环统一管。
  • 给大厅/竞技场：非对局死亡按所在世界用对应重生点。
  • 给统计：死亡/击杀在此计入战绩。
  • 给技能系统：重生重发技能物品。
  • 给边界：坠落清速度逻辑在边界/反作弊处。

5. 设计红线与边界

  • 即时重生默认开：关掉后走原生重生，可能丢对局内装备逻辑，破坏平衡。
  • 背包保留仅对局内：非对局世界不受此约束。
  • 指令黑名单要随版本维护：新增破坏类命令必须补进列表，否则成漏洞。
  • 虚空环境需配平台：重生点若无台子仍会坠空，须配合落点设置。
  • 旁观者不受冻结：移动/指令封锁只针对参与者与旁观。

十、统计与排行

1. 这个系统要解决什么

玩家需要成长感与炫耀资本。统计系统把每局表现沉淀成个人战绩，并用排行榜让"谁更强"可视化，支撑长期留存与轻量竞争。

2. 玩家实际经历什么

  • 每局结束，系统按胜负给攻防双方记胜/负、加场次；击杀、死亡、破标各自累计。
  • 玩家可随时用命令查排行榜，按胜场 / KDR / 击杀 / 死亡 / 破标 / 场次 排序，分页浏览。
  • KDR（击杀死亡比）0 死亡且有过击杀时记为极大值，避免"除零"，也直观体现"全胜战神"。

3. 关键数值与平衡基线

字段含义设计意图
胜/负局数核心战力标签
击杀/死亡个人对抗KDR 来源
破标团队贡献鼓励"拆"而非只"杀"
场次参与度长期留存指标
KDR击杀/死亡（0死→极大值）排行榜常驻维度
每页10 条信息密度适中

4. 它和别的系统怎么咬合

  • 给核心流程 / 事件：对局结束事件触发战绩结算。
  • 给指令：排行榜命令读取排行数据。

5. 设计红线与边界

  • 单人库并发：SQLite 单文件，高频写需串行；当前由主线程事件驱动，压力可控。
  • KDR 边界：死亡为 0 时给极大值占位，避免除零并体现全胜。
  • 名称冗余存库：UUID 为主键防改名丢数据，名字冗余便于展示。
  • 旁观/未参与不计：只统计真正参与者，避免刷数据。

十一、配置与指令

1. 这个系统要解决什么

设计师/服主需要一把"调音台"：能不改代码就调对局参数、划战场、发规则。命令与配置文件就是这把台子，决定了这局游戏长什么样。

2. 服主实际会做什么

  • 调对局参数：信标数量、对局时长、放置时长、装备层级——这些是"节奏旋钮"。注意：对局时长按分钟、放置时长按秒。
  • 划战场与设重生点：用木锄框出竞技场范围，设定攻/防/旁观三方出生点。
  • 发规则与排行展示：规则文本、展示牌内容可配置；排行榜由统计系统提供。
  • 玩家侧命令：加入/退出队列、看竞技场列表、查排行、看技能信息、求帮助。
  • 管理员命令：开局/停局、改参数、设重生点、划区域、放规则牌、发规则书、调技能等。

3. 关键数值与平衡基线（旋钮范围）

参数代码允许界面限制设计提示
信标数≥11–10体验上限以界面为准
对局时长1–120 分钟1–60 分钟过长节奏松、过短无博弈
放置时长10–300 秒±10太短新手来不及
装备层级4 档循环切换统一 baseline 防碾压

4. 它和别的系统怎么咬合

  • 配置驱动所有系统：对局参数→核心流程，出生点/区域→竞技场，技能数值→技能系统，世界/落点→大厅，规则文本→展示。
  • 命令是唯一修改运行期配置与触发对局的入口（NPC 传送除外）。

5. 设计红线与边界

  • 钳制不一致是隐患：代码与界面范围不同（见上表），以界面标注为体验上限，避免玩家误设极端值破坏节奏。
  • 运行期写入：落点/重生点/NPC 位置由命令写回配置，需保存。
  • 对局中禁改：非空闲状态拒绝改参数/换边，防止对局中篡改导致状态撕裂。
  • 权限两级：仅 管理员 / 玩家；管理员豁免边界与指令封锁。
  • 双语维护：新增提示文案须同步中英文，否则回退默认。

十二、自定义事件与扩展点

1. 这个系统要解决什么

一款好的对抗插件不该是"黑盒"。它要对外暴露关键时刻的信号和实时数据接口，让其他插件（统计、积分、广播、占位符）能搭车，也让未来扩展有清晰入口。这是"可生长性"的设计。

2. 对外暴露了什么

关键时机信号（自定义事件）：

  • 对局开始（带攻防名单与世界）
  • 对局结束（带胜负）
  • 信标被拆（带下手人、位置、剩余数——剩余 0 即攻方胜）
  • 技能释放（带释放者、技能 ID、位置）
  • 技能解锁（带玩家、路线、层级 1–3）

实时数据接口（占位符）：支持 PlaceholderAPI 时，可读取剩余信标、对局状态、攻防人数、剩余时间、上次胜负、技能路线/层级/击杀/冷却等。

扩展入口：想加事件→在对局事件系统加一个"百分比触发点"；想加技能→先在技能配置加路线/层级；想加 HUD 段→在顶部条/行动条追加（注意长度上限）；想加统计→加字段 + 排行榜分支。

3. 关键数值与契约基线

信号关键字段设计意图
信标被拆剩余数（0=攻方胜）监听方可据此判定胜负，不必自己算
技能解锁层级 1–3对应 t1/t2/t3，便于外部展示
上次胜负ATTACKER/DEFENDER/NONE无对局时给 NONE，避免歧义

4. 它和别的系统怎么咬合

  • 给核心流程：开局/结束事件由主循环发出。
  • 给信标系统：信标被拆事件桥接破标与统计/外部监听。
  • 给技能系统：释放/解锁事件暴露技能行为。
  • 给统计：对局结束事件触发战绩自动结算。

5. 设计红线与边界

  • 事件只通知、不改状态：监听方不应在对局内部事件里反向改核心状态，避免竞态。
  • 占位符依赖 PAPI：无 PlaceholderAPI 时静默跳过，不报错。
  • 数值驱动优先：技能/事件尽量走配置，降低改动成本。
  • 临时实体必清理：终局高亮等支架/粒子任务须回收，扩展事件同理——否则泄漏到下一局。
  • 向后兼容：新增事件/占位符须保留旧契约，不破坏既有监听插件。
